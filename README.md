# SMC PinSweep EA (MT5)

Советник для MetaTrader 5. Тренд определяется по рыночной структуре на двух
таймфреймах — старшем (`InpTrendTF`, по умолчанию H4) и ТФ входа (`InpEntryTF`,
по умолчанию H1, был D1+H1) — вход по одному из трёх независимых триггеров
на ТФ входа: пинбар, снявший ликвидность, поглощение по тренду, или снятие
недельной ликвидности (PWL/PWH) с CHoCH на ТФ входа. Все три работают
параллельно (не ИЛИ) — подробная схема в `ENTRY_LOGIC.md`.

## Логика

### 1. Тренд (контекст)

Определяется независимо на **старшем ТФ** (`InpTrendTF`) и **ТФ входа**
(`InpEntryTF`) через свинг-структуру (`SwingStructure.mqh`), которая хранит
**историю** свингов за `InpHistoryBarsD1`/`InpHistoryBarsH1` баров, а не
только последний:

- Свинг-хай/лоу — фрактал с окном `N` баров слева и справа (по умолчанию 2).
  Подтверждается только после закрытия `N` баров справа.
- **BOS** (Break of Structure) — пробой последнего свинга **в сторону** текущего тренда.
- **CHoCH** (Change of Character) — пробой **против** тренда, меняет состояние.
- Пробой считается по **close** закрытого бара (`InpBreakByClose = true`).
  Это принципиально: снятие ликвидности хвостом не должно ломать структуру.
- Каждый свинг помечается `swept` при использовании как уровень входа —
  повторно тот же уровень для сигнала не берётся, пока не выпадет из окна истории.

Торговля разрешена **только при строгом совпадении** тренда на обоих ТФ —
кроме сетапа снятия PWL/PWH (см. ниже), у него CHoCH на `InpEntryTF` сам
по себе уже смена тренда, ждать подтверждения от `InpTrendTF` не нужно.

### 2. Триггеры входа

На последнем **закрытом** баре ТФ входа проверяются **все три** триггера
независимо (`TryPWSweepEntry`, `TryPinBarEntry` и `TryEngulfingEntry`, если
`InpUseEngulfing`) — если сработало несколько и есть место по
`InpMaxPositions`, встанут все соответствующие лимитки.

Общие для всех трёх, проверяются раньше любого из триггеров:

1. **Спред** — пропуск, если больше `InpMaxSpreadPoints`.
2. **Токсичный час** (`InpUseHourFilter`, вкл. по умолчанию) — не открывать
   новые в окне `InpBlockHourStart`..`InpBlockHourEnd` по времени сервера
   (по умолчанию 08–11). На бэктесте 2018-2025 винрейт **всех трёх** сетапов
   синхронно проседает в этот час (~30% → ~17%), не отдельного сетапа —
   похоже на структурный эффект сессии (08–11 по серверу UTC+2 ≈ 06–09 UTC,
   ранний Лондон), а не совпадение. Исключение окна подняло P&L +72.0% →
   +85.0% и почти вдвое снизило просадку (~9.3% → ~5.8%). Калибровка на трёх
   точках (07–12/08–11/09–10) — 08–11 локальный максимум, шире и уже хуже.
   Уже выставленные лимитки не отменяются, только новые не открываются.

Дополнительно только для пинбара/поглощения (снятие PWL/PWH — свои фильтры,
см. ниже):

3. **Размер свечи** — диапазон бара должен быть не меньше `InpMinRangeATR * ATR(InpATRPeriod)`
   на ТФ входа (0 отключает фильтр). Причина отбраковки и фактические числа попадают
   в `SIGNAL_REJECTED` в CSV-логе — по ним и калибруется порог.

Дальше у каждого триггера своя геометрия свечи:

**Пинбар** (`PinBar.mqh`)
- Доминирующий хвост ≥ `InpMinTailRatio` от полного диапазона свечи, строго
  больше противоположного (отсекает доджи). Направление — по тренду.
- **Снятие ликвидности** (обязательно только для пинбара) — хвост вышел за
  ближайший ещё не снятый свинг на ТФ входа, но закрытие вернулось внутрь:
  - Покупка: `low < swingLow` **и** `close > swingLow`
  - Продажа: `high > swingHigh` **и** `close < swingHigh`

**Поглощение** (`Engulfing.mqh`)
- Тело текущей свечи полностью перекрывает тело предыдущей (классическое
  bullish/bearish engulfing), отношение тел в диапазоне
  `[InpMinEngulfBodyRatio, InpMaxEngulfBodyRatio]` (верхняя граница отключается
  нулём). Слишком крупные поглощения на бэктесте 2018-2025 стабильно хуже
  умеренных — похожи на истощение движения, а не продолжение.
  Направление — по тренду. Снятие ликвидности **не требуется**.

**Снятие PWL/PWH** (`WeeklySweep.mqh`) — самостоятельный сетап, не зависит
от `InpTrendTF`/`InpEntryTF`-совпадения и не проходит через ATR/премиум-
дискаунт фильтры ниже:
- `CWeeklySweep` хранит хай/лоу прошлой календарной недели (`PERIOD_W1`,
  бар 1). Снятие — хвост `InpEntryTF`-бара выходит за уровень, закрытие
  возвращается обратно (классический liquidity grab), раз в неделю на
  уровень (флаг одноразовый, сбрасывается с началом новой недели).
- После снятия ждём (не обязательно на этом же баре) первый CHoCH на
  `InpEntryTF` в соответствующую сторону (PWL → CHoCH_BULL, PWH → CHoCH_BEAR).
  Совпадение проверяется по `LastEventTime()` структуры — событие должно
  быть именно с текущего бара, не старое.
- Вход считается от свечи **самого CHoCH-пробоя** (может быть другим баром,
  чем свеча снятия PWL/PWH), геометрия как у поглощения — откат
  `InpPWSweepEntryRetrace` в тело этой свечи.

Общие для пинбара/поглощения финальные фильтры:

4. **Новости** (`InpUseNewsFilter`) — фиксированное дневное окно по серверному
   времени: `InpNewsHourServer:InpNewsMinuteServer` ± `InpNewsMinsBefore`/`InpNewsMinsAfter`
   (по умолчанию 14:00–15:00, сейчас сервер брокера на UTC+2). Экономический календарь
   не используется — `CalendarValueHistory()` ненадёжна в тестере стратегий.
   Применяется и к снятию PWL/PWH тоже, в отличие от ATR/премиум-дискаунт.
5. **Премиум / дискаунт** (`InpUsePremiumFilter`) — откат сигнальной свечи от
   границы диапазона должен быть не меньше `InpMinRetracement` (общий нижний порог
   для обоих сетапов). У поглощения дополнительно есть верхний потолок
   `InpMaxEngulfRetracement` (0 = без потолка) — на бэктесте 2018-2025 глубокий
   откат работает у поглощения **хуже**, а не лучше (обратная зависимость по
   сравнению с пинбаром). У пинбара своя аномалия — «мёртвая зона» отката
   65–90%, стабильно убыточная на том же бэктесте, при том что и более мелкий,
   и более глубокий откат прибыльны. `InpPinbarDeadZoneLow`/`InpPinbarDeadZoneHigh`
   вырезают именно эту зону (0 у `Low` отключает вырез). Границы диапазона —
   одна импульсная нога: свежий экстремум по тренду (свинг-хай для BULL,
   свинг-лоу для BEAR) и ближайший противоположный экстремум перед ним по времени.

### 3. Вход и управление сделкой

Вход **лимитный** у всех триггеров, но откат считается по-разному:

```
Пинбар:     entry = bodyEdge ∓ InpEntryRetrace * tail             (откат внутрь хвоста)
Поглощение: entry = close ∓ InpEngulfEntryRetrace * (close-open)   (откат внутрь тела)
PWL/PWH:    entry = bodyTop/Bottom ∓ InpPWSweepEntryRetrace * body (откат внутрь тела CHoCH-свечи)
```

(знак `∓` — минус для BUY, плюс для SELL; для пинбара `bodyEdge` = нижний/верхний
край тела, `tail` = длина соответствующего хвоста; у PWL/PWH откат считается через
`bodyTop`/`bodyBottom = max/min(open, close)`, а не через `close∓ratio*(close-open)`
напрямую, как у поглощения — цвет CHoCH-свечи не гарантирован направлением пробоя
(пробой считается по `close` относительно уровня структуры, не по цвету свечи), так
что формула через close-open могла бы откатывать не в ту сторону на редкой свече
«не того» цвета; на обычной свече число то же самое)

- **Стоп:** за экстремум сигнальной свечи (`low`/`high`) + буфер `InpSLBufferPoints`
  — общий параметр для всех триггеров.
- **Тейк:** фиксированный R:R (`InpRiskRewardRatio`) от лимитной цены, а не от рынка
  — общий параметр для всех.
- **Срок жизни лимитки:** `InpPendingLifeBars` баров ТФ входа (по умолчанию 1),
  возраст считается в барах через `iBarShift`, с учётом `SYMBOL_TRADE_FREEZE_LEVEL`.
- **Объём:** от процента риска на баланс (`InpRiskPercent`) либо фиксированный лот
  (`InpFixedLot`, если риск % = 0).
- Проверяется `SYMBOL_TRADE_STOPS_LEVEL` и то, что цена не ушла за уровень
  лимитки — иначе сигнал пропускается.
- **Перенос в безубыток** (`InpUseBreakeven`, по умолчанию **включён**, триггер
  `InpBreakevenTriggerR = 2.0`) — при достижении заданного R (от изначального
  риска) стоп переносится на вход + буфер `InpBreakevenBufferPoints`. Триггер
  важно не ставить слишком рано: на бэктесте +1R почти не улучшает просадку,
  зато режет много будущих TP на середине пути (P&L +41.8% → +28.2%), а +2R
  почти не трогает победы (61 TP из 64 базовых) и даёт небольшой плюс сразу
  по обеим метрикам (+42.3% P&L, просадка -8.9% против -9.1% без б/у) —
  подробнее в `OPEN_QUESTIONS.md`.
- **Трейлинг-стоп** (`InpUseTrailingStop`, выкл. по умолчанию) — начиная с
  `InpTrailingStartR`, стоп подтягивается на фиксированную `InpTrailingDistancePoints`
  от текущей цены. Стоп двигается только в сторону прибыли, TP не трогается.
  Оба механизма реагируют на каждый тик (`ManageOpenPositions`), не ждут закрытия бара.
  На бэктесте (R:R=4.0) обе проверенные точки — старт 1.5R/дистанция 200п и
  старт 2.5R/дистанция 400п — оказались минусом по P&L (+57.3% без трейлинга
  против +56.6% и +55.0% соответственно): победители в основном идут одним
  движением до TP без глубоких откатов, трейлинг просто срезает часть прибыли,
  почти ничего не спасая взамен. Оставлен выключенным, подробнее в
  `OPEN_QUESTIONS.md`.
- **Выходные:** по пятницам после `InpFridayNoNewHour` новые сделки не открываются,
  после `InpFridayCloseHour` всё закрывается (`InpCloseBeforeWeekend`).

### 4. Логирование

Все сигналы, отказы и исполнения пишутся в `SMC_<символ>_<magic>.csv` в
`Common\Files` (`InpWriteCsvLog`) — общий для всех терминалов, переживает
переустановку. Формат и события описаны в `DEVELOPMENT.md`. `PENDING_PLACED`
содержит `setup=pinbar|engulf`, чтобы отличать источник сигнала — но
`FILLED`/`CLOSED` этот тег пока не наследуют, так что P&L по каждому триггеру
отдельно из лога на сегодня не восстановить (см. `OPEN_QUESTIONS.md`).

```

    ├── Engulfing.mqh                 — детекция поглощения, причина отбраковки

```

## Установка

Для разработки с симлинками и CLI-компиляцией — см. `DEVELOPMENT.md`.
Быстрый путь вручную:

1. В MT5: `Файл → Открыть каталог данных`.
2. Скопировать содержимое `MQL5/` поверх одноимённой папки каталога данных
   (или сделать симлинк на репозиторий — `./scripts/link-to-mt5.sh`).
3. Открыть `SMC_PinSweep_EA.mq5` в MetaEditor, `F7` — компиляция.
4. Прогнать в тестере стратегий на режиме **«Каждый тик на реальных тиках»**.

## Параметры, которые стоит подбирать первыми

| Параметр | Смысл | Комментарий |
|---|---|---|
| `InpTrendTF` | старший ТФ структуры | по умолчанию H4 (был D1); H4 на бэктесте обошёл D1 |
| `InpEntryTF` | ТФ входа/сигнала | по умолчанию H1 — меняет масштаб вообще всего: ATR, историю свингов, срок жизни лимитки. На бэктесте H1 заметно обошёл M15 и M30 (M30: 375 сделок, винрейт 15.2%, P&L -16.9%, просадка ~23.8%) |
| `InpRiskRewardRatio` | R:R | по умолчанию 4.0 — на бэктесте (H4/H1) обошёл 1.8/2.0/2.5/3.0, дальше 5.0 уже хуже (см. текст ниже) |
| `InpUseBreakeven`/`InpBreakevenTriggerR` | перенос в б/у | по умолчанию вкл., триггер 2.0 — 1.0 резал доходность вдвое, 2.0 почти бесплатен (см. текст выше) |
| `InpUseTrailingStop`/`InpTrailingStartR`/`InpTrailingDistancePoints` | трейлинг-стоп | выкл. по умолчанию — обе проверенные точки (1.5R/200п и 2.5R/400п) дали минус по P&L, см. текст выше |
| `InpUsePWSweep`/`InpPWSweepEntryRetrace` | вход по CHoCH после снятия PWL/PWH | по умолчанию вкл., откат 0.50 — на бэктесте локальный максимум среди 0.30/0.50/0.65 (мельче и глубже хуже по вкладу в P&L) |
| `InpUseHourFilter`/`InpBlockHourStart`/`InpBlockHourEnd` | запрет входа в токсичный час | по умолчанию вкл., окно 08–11 (сервер) — локальный максимум среди 07-12/08-11/09-10, см. текст выше |
| `InpMinTailRatio` | порог хвоста пинбара | 0.40 даёт много сигналов; попробовать 0.55–0.66 |
| `InpMinRangeATR` | мин. размах свечи в ATR | не измерено, см. `OPEN_QUESTIONS.md` |
| `InpMinEngulfBodyRatio` | во сколько раз тело больше предыдущего | 1.0 = просто поглощение, без запаса |
| `InpMaxEngulfBodyRatio` | потолок того же отношения | 2.0 по умолчанию — огромные поглощения хуже умеренных на бэктесте, 0 отключает |
| `InpMaxEngulfRetracement` | потолок отката для поглощения | 0.70 по умолчанию — глубокий откат у поглощения работает хуже, 0 отключает |
| `InpEngulfEntryRetrace` | откат в тело поглощения | 0 = вход по close, 1 = откат до open |
| `InpSwingBarsH1` | размер свинга на ТФ входа | 2 = мелкая структура, 4–5 = крупная |
| `InpSwingBarsD1` | размер свинга на старшем ТФ | обычно достаточно 2 |
| `InpEntryRetrace` | глубина отката в хвост | 0 = вход от тела, больше = глубже и реже налив |
| `InpPendingLifeBars` | жизнь лимитки | 1 бар даёт много пропусков, попробовать 2-3 |
| `InpMinRetracement` | мин. откат для премиум/дискаунт | 0 отключает фильтр по сути |
| `InpPinbarDeadZoneLow/High` | вырез отката 65–90% для пинбара | обе границы прибыльны, середина стабильно в минусе на бэктесте |
| `InpSLBufferPoints` | буфер стопа | зависит от инструмента и спреда |
| `InpBreakByClose` | тип пробоя | `false` резко меняет поведение структуры |

Актуальный статус открытых вопросов и решений — в `OPEN_QUESTIONS.md`.

## Результаты бэктеста (текущие дефолты)

EURUSD, H4/H1, реальные тики, депозит 10000, риск 0.5%/сделку:

| Период | Сделок | Винрейт | P&L | Просадка |
|---|---|---|---|---|
| 2018–2025 (текущие дефолты: R:R=4.0, б/у вкл. триггер 2.0, PWSweep вкл., токсичный час 08–11 вкл.) | 230 | 30.0% | +85.0% | ~5.8% |
| 2018–2025, без `InpUseHourFilter` (для сравнения) | 316 | 25.9% | +72.0% | ~9.3% |
| 2018–2025, без `InpUsePWSweep` (для сравнения, тоже без фильтра часа) | 186 | 27.4% | +57.3% | ~9.5% |
| 2018–2025, R:R=3.0 (для сравнения, без PWSweep/фильтра часа) | 186 | 32.8% | +42.3% | ~9.1% |
| 2018–2025, R:R=5.0 (для сравнения, без PWSweep/фильтра часа) | 186 | 21.5% | +51.3% | ~9.1% |
| 2015–2017 (не участвовал в подборе параметров, текущие дефолты) | 87 | 25.3% | +12.7% | ~4.5% |

R:R подобран перебором трёх точек на одном и том же наборе из 186 сделок
(меняется только дистанция TP, сигналы и вход те же): 3.0 → 4.0 даёт рост
P&L на ~15 п.п. почти без изменения просадки, 4.0 → 5.0 уже хуже — винрейт
падает быстрее, чем растёт средний выигрыш. 4.0 — локальный максимум среди
проверенного, не полный перебор диапазона.

`InpUsePWSweep` добавляет треть сделок (130 из 316) и чистый плюс к P&L
(+13.8% из 72.0%, вклад сетапа посчитан последовательным сопоставлением
`PENDING_PLACED`→исход в CSV-логе, корректно при `InpMaxPositions=1`) почти
без роста просадки. `InpPWSweepEntryRetrace` откалиброван на трёх точках:
0.30 даёт больше исполнений (36% лимиток протухает вместо 54%), но хуже
качеством (вклад +$1039 вместо +$1378 на депозит 10000); 0.65 — ещё меньше
исполнений (63% протухает) и ещё хуже (+$805). 0.50 — локальный максимум.

`InpUseHourFilter` (окно 08–11 по серверу) нашёлся через разбивку сделок по
часу выставления: винрейт **всех трёх** сетапов синхронно проседает с ~30%
до ~17% именно в эти четыре часа (совпадение по всем трём независимым
сетапам сразу — довод в пользу структурного эффекта сессии, а не шума
одного сетапа). Исключение окна даёт +72.0%→+85.0% P&L и ~9.3%→~5.8%
просадки — улучшение сразу по обеим метрикам, а не размен одной на другую.
Калибровка границ на трёх точках: 07–12 (шире) даёт только +67.1% — задел
прибыльный час 07; 09–10 (уже) — +77.7%, недобирает часть эффекта. 08–11 —
локальный максимум.

Параметры калибровались вручную по прогонам на EURUSD 2018-2025 — то есть
результат на этом периоде **не независимая проверка**, а то, на что и
подгонялись пороги (риск переобучения). На 2015-2017 (эти годы в подборе
не участвовали) результат теперь держится заметно лучше, чем раньше
(+12.7% против почти нуля на более ранних версиях бота) — единственный
убыточный год во всём периоде 2015-2025 это сам 2015 (-$140, ~-1.4% от
депозита), 2016-2017 уже в плюсе. На других парах с теми же параметрами
эдж **не воспроизводится**: GBPUSD 2018-2025 на настройках до фильтра часа
— винрейт 20.8%, P&L -13.6% (не перепроверялось после PWSweep/фильтра часа,
см. `OPEN_QUESTIONS.md`). Считать бота настроенным конкретно под EURUSD, не
универсальным мультивалютным — переносить параметры на другие пары без
отдельной калибровки не стоит.

Годовая разбивка на EURUSD 2015-2025 с текущими дефолтами: **все годы, кроме
2015, прибыльны**, включая 2022-2024, которые раньше (до PWSweep и фильтра
часа) были тремя убыточными годами подряд — похоже, оба улучшения частично
устранили ту режим-зависимость, а не просто добавили доходности поверх неё.
Утверждать это уверенно рано — обе калибровки (PWSweep, фильтр часа) сделаны
на том же окне 2018-2025, где сидели и убыточные 2022-2024, так что часть
эффекта может быть подгонкой именно под них, а не универсальным улучшением.

## Известные ограничения

- Перенос в безубыток (`InpUseBreakeven`, вкл. по умолчанию) и трейлинг
  (`InpUseTrailingStop`, выкл. по умолчанию) есть. TP всегда остаётся потолком:
  сделка либо закрывается по нему как обычно, либо раньше по подтянутому стопу.
  R для триггеров считается от изначального риска на момент филла, не
  пересчитывается при движении стопа.
- Лимитка не переставляется: если цена не дошла до уровня за отведённые
  бары, сигнал теряется целиком. Доля пропущенных входов — метрика
  для настройки `InpEntryRetrace`.
- Риск считается независимо на каждый символ/график — при нескольких
  инструментах с одним `InpRiskPercent` суммарный риск на баланс растёт
  пропорционально их числу (см. `OPEN_QUESTIONS.md`).
- Частичное исполнение лимитки не обрабатывается (сознательное решение).
- Новостное окно фиксированное и завязано на серверное время брокера —
  при смене летнего/зимнего времени сервера его нужно поправить вручную.
- Таймфреймы структуры и входа задаются `InpTrendTF`/`InpEntryTF`, а не
  привязаны к таймфрейму графика — советник можно вешать на любой ТФ.
  Историю/ATR/срок жизни лимитки после смены ТФ стоит перепроверить —
  число баров в тех же входах будет означать другой охват по времени.
